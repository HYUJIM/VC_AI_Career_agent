## 과제·실험 단위

제안 과제: JD에 맞춘 짧은 포트폴리오 섹션(보유 경력/교육/프로젝트 요약, 근거 ID, 부족 역량 및 향후 학습 제안). 분량·문장 수·출력 토큰 상한은 파일럿 후 본 평가 전에 고정한다. 보유 사실과 미래 추천을 구분하며 JD 요구만으로 보유 역량을 추론하지 않는다. 프로필에는 식별/배경만 공통 제공하고 평가할 보유 사실을 숨겨서 근거 제거 효과를 유지한다.

case = profile × JD × noise type × noise level; paired key=case_id+generation seed. 같은 인물/원천 자료 및 파생 JD·노이즈는 family_id로 묶고 family 전체를 dev/test 중 한쪽에만 배정한다. 독립 표본수는 family 수다. A/B/C와 seed 반복을 독립 표본으로 세지 않는다.

V_raw=스키마 유효 전체 근거, V_eligible=고정 정책에 적격인 근거, T=검증 상태와 독립적으로 사람이 확인한 사실 기준. 스키마 격리 전 자료는 별도 quarantine 목록이다. 허용 주장 목록은 T의 범위와 출처를 명시하고 폐쇄세계 가정 여부를 기록한다. T 누락은 거짓이 아니라 unknown이다. 서명 유효도 사실 참의 충분조건이 아니다.

## 조건 통제

A_no_rag: 근거 없음. B_naive_rag: 동일 고정 후보 전체. C_verified_rag: 동일 후보에 검증 적격 필터만 적용, 재충원 없음. 모델 revision/토크나이저/프롬프트/JD/프로필/출력 예산/seed 동일. 후보 순서는 C에서도 보존한다. 상태·정답·노이즈·제외 이유는 생성 프롬프트에서 제외한다. A도 근거전용 지시를 받으므로 일반지식 성능 기준선으로 해석하지 않는다.

현재 ListRetriever/FixedCandidateRetriever는 의미 검색이 아니다. 최소 실험의 결론은 고정 후보 조건의 필터 효과로 제한한다. C의 문맥 길이 감소는 필터 총효과의 일부이며 순수 암호 연산 효과라고 부르지 않는다. 조건 실행 순서를 seed로 균형화하고 실패까지 기록한다. 입력 예산 초과는 사전 탐지하며 조용한 truncation/조건별 후보 변경 금지. length 종료는 원문 그대로 평가하고 불완전 출력으로 별도 집계한다.

## 정답·주장·오류 정의

사람이 출력의 원자적 사실을 분해한다. 거절 이유의 사실 주장도 포함한다. 원문 span은 Unicode code point [start,end)이다. entity_id/attribute/value/unit/time_scope로 정규화하되 원래 ID·명칭·원문은 보존한다. 반복된 같은 명제는 canonical_key 하나와 여러 spans로 표현한다. 다른 값/시점의 모순 명제는 별개다. 자동 문자열 비교로 사실 판정하지 않는다.

모든 축은 yes/no/unknown/not_applicable. factual_correctness는 T와 비교, context_support는 실제 제공 문맥과 비교, evidence_eligibility는 고정 정책과 비교한다. citation_correct는 실제 인용과 문맥 및 지지 관계를 판정한다. 결측=0 금지, 이수량과 달력 기간 환산 금지, 역할/직급 단순 대소 비교 금지.

주 오류 유형은 상호배타 F(근거 없는 새 개체/보유 주장), O(기존 개체의 속성 왜곡), other, none, unknown. 유형은 원인 설명이며 사실 오류율을 대신하지 않는다. O의 upward 태그는 같은 단위/시점의 순서 비교가 정당할 때만 부여한다. F는 V_raw의 지원 부재이지 현실의 거짓 선언이 아니다. jd_aligned=yes는 JD 요구와 연결됨을 뜻한다. D_JD는 F 중 JD 관련인 하위집합; F+D_JD를 총 오류로 합산하지 않는다. 악의/기만 의도는 판정하지 않는다. 추천 문장은 assertion_kind=recommendation으로 구분한다.

## 지표 및 분석 계획 — 팀 승인 대기

주 지표 제안: 사람 확정 원자 주장 factual_correctness=no / (yes+no), B−C 차이(양수이면 C 오류 감소). 이것을 문맥 비지지율이나 VC 부적격률과 혼용하지 않는다. 최소 코드는 개별 응답의 분자/분모만 반환하며 최종 통계는 구현하지 않는다.

각 case/seed에서 B와 C 양쪽의 비율이 정의된 경우 차이를 구한다. family 내 case/seed 차이를 평균하고 family 간 동일 가중 평균한다. 각 노이즈 층도 별도 보고한다. family 단위 대응 bootstrap 95% CI 제안(횟수/seed/최소 family 수와 표본수 근거는 동결 전 확정). primary 검정 1개, 다중 보조 비교는 탐색적으로 표시한다. unknown, 주장0, 실패 때문에 정의되지 않는 쌍의 수와 유형을 공개하며 완전쌍 분석을 전체 실행 성능으로 표현하지 않는다.

필수 동반 지표: context_support=no/(yes+no), evidence_eligibility=no/(yes+no), citation_correct=yes/(yes+no), F/O 및 F의 JD 하위 건수, 전체 주장 수, unknown 비율, 응답 길이, 응답/혼합/거절률, task_correct, abstention_correct. 필수 사실 커버리지=중복 없이 정확히 표현된 required_fact_ids 수/전체 required_fact_ids 수; 분모0=null. 필수 사실은 조건에 무관하게 사전 고정한다. 답변 가능성은 조건별 제공 문맥에 따라 별도 gold를 둔다. 근거가 없는 A의 적절한 거절과 과제 유용성은 구별한다.

전면 거절의 주장0 오류율은 null이다. 오류 감소만으로 우월성을 선언하지 않고 커버리지·과잉 거절·실패를 함께 비교한다. ledger의 예정 실행 전체를 분모로 성공/실패/누락/length 비율을 보고한다. 생성 실패를 오류0 또는 주장1 오류로 바꾸지 않는다. 본 실행 자동 재시도 없음 제안; 복구 실행은 새 attempt_id로 남기고 최초 예정 결과를 대체하지 않는다.

HSI는 탐색적 제안만 보존: 팀 원안 (1.0 F + 0.5 O + 1.2 D_JD)는 D_JD의 이중 가산이 있어 주 지표로 사용하지 않는다. 사용한다면 'JD 추가 벌점'을 명시하고 원자 주장 공통 분모, 미확인 제외 수, 가중치 민감도 범위를 사전 합의한다. 이번 코드는 HSI를 계산하지 않는다.

Ragas Faithfulness는 제공 문맥에 의해 지지되는 주장 비율이며 전체 사실 진실성/VC 적격성을 대체하지 않는다. 공식 정의 재확인: https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/ (2026-10-09). 채택 시 패키지·metric class·judge revision·프롬프트·재시도·파싱 실패 정책을 동결한다. 자동 judge 결과는 별도 양식이며 사람 승인 입력으로 승격하지 않는다. 20% 대조·상관0.85는 정확성 보증이 아니다.

## 노이즈 계약

목표 비율 0/10/30/50/70%는 V_raw 문서 개수 분모의 제안이다. 전체 크기10의 배수인 고정 풀에서 비필수 distractor를 대체하고 필수 정답 근거는 동일하게 유지하는 안을 권고한다. 70% 조건에도 필수 근거를 유지할 수 있는지 먼저 점검한다. 불가능하면 풀 크기/설계를 동결 전에 변경한다. top_k=2로 10/30/70% 후보 노이즈를 정확히 만들 수 없다.

raw/candidate/final context 각각 noise_count/total_count와 실제 비율을 기록한다. 무문맥 비율=null. 문서 단위 비율과 토큰 노출량은 다르며 토큰 수도 별도 기록한다. 목표 비율로 실제 비율을 덮어쓰지 않는다. 노이즈 문서 ID 집합을 고정한다. 유형: forged_signature, revoked, expired, untrusted_issuer, valid_conflict. 하나의 실험 층은 단일 유형을 우선 사용한다. 혼합은 조성과 관련성·길이를 별도 동결한다. valid_conflict는 양쪽 verified가 가능하며 필터 해결을 가정하지 않는다. 충돌 시 gold는 보류/충돌 설명을 지정한다.

## 사람 검토

dev 사례로 분해 지침을 맞춘 뒤 test 출력은 서로 다른 두 사람이 독립 평가한다. 조건/모델/검증 상태는 1차 패킷에서 숨기고 순서를 섞는다. 문맥 양으로 추정 가능하므로 완전 눈가림은 아니다. 정답/정책을 가진 2차 키는 별도 접근한다. 두 원검토 파일 해시, 검토자 ID·시간대 포함 시각, 중재 근거를 보존한다. 불일치는 합의 또는 제3자 중재; 미해결은 disputed. 최초 판정의 일치율/축별 혼동표를 중재 후 점수와 분리한다.
