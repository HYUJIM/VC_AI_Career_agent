## v1 범위 및 불변 조건

BE 전용의 제한된 한국어 규칙 기반 구조화이며 범용 자연어 추출기가 아니다. 기존 A/B/C, BE adapter, 3건 진단 및 기존 review 파일은 변경하지 않는다. backend_status는 보존하되 교육 여부나 실제 VC 검증 증거로 사용하지 않는다. paper_evaluation_eligible=false.
입력은 기존 검증된 BE export이다. 원본 export와 source hash를 보존하며, export에 없는 raw_data 확장 필드는 해석하지 않는다. 미제공은 이 입력 범위에서 미제공이라는 뜻이다.
subject_did와 record_id는 기존 export validator로 검증한다. 전체 배치의 다른 사용자 및 UUID 중복은 중단한다. 원본 name/ID는 그대로 표시하고 모델 원답변을 수정하지 않는다.

## 선택 정책

목표는 명시적인 교육/과정 수료 기록이다. 교육/과정/부트캠프/아카데미/캠프/테크코스와 수료/이수 표현이 함께 있으면 후보로 선택한다. 기사·자격증·어학시험·대회 수상·기여 인증 등 명시적인 비대상 단서는 제외한다. 두 단서가 동시에 있거나 부정·예정 표현, 맥락 불명, 유형만 있고 의미가 불명확하면 보류한다. 교과 성적 A+만으로 수료를 확정하지 않는다. Completion/Certificate라는 유형만으로 교육을 확정하지 않는다. 선택/제외/보류 모두 근거 인용을 남긴다. 이 규칙은 데이터셋 밖 의미 정확성을 보장하지 않는다.

## 값 및 결측

course_duration과 completion_hours를 분리한다. 각 필드: value, unit, status, evidence[{path, quote, start, end}], method. 단위는 원문대로 보존하며 달력 기간을 시간으로 환산하지 않는다. 분은 hours로 자동 변환하지 않는다. issued_at/expires_at을 수강 시작/종료로 해석하지 않는다.
status: provided(명시 근거), not_provided(검사 대상 원문에 관련 표현 없음), ambiguous(계획/범위/관계 모호), conflicting(다른 명시 값), unassessable(지원하지 않는 표현). 결측 값은 null이며 0 또는 not_applicable로 대체하지 않는다. 원문에 0시간 이수가 명시된 경우에는 0을 보존한다.
v1은 숫자+개월/주/일/년의 과정 기간과 숫자+시간 이수/수료 표현을 보수적으로 처리한다. 문맥상 기간인지 모호한 숫자, 주당/일일 시간, 계획/부정/범위, 한글 수사, 분 단위는 보류한다. 여러 단위의 동시 표현도 자동 환산하지 않고 보류한다. 지원 밖 표현을 사실 오류로 단정하지 않는다.

## 출력과 평가

원본 기반 표시: 교육명 | 과정 기간 | 이수 시간 | record_id. 미제공은 '기간 미제공'/'시간 미제공', 보류는 '확인 필요'. 모델 원답변, 구조화 JSON/표시, 검토 JSON은 각각 저장한다.
선별: expected selected/rejected/review와 비교하고 TP/FP/FN 및 보류 수를 보고한다. 정답이 보류인 항목을 선택하면 오선택으로 계산한다. 보류로 낮은 커버리지를 숨기지 않는다.
생성: oracle(사전 정답 ID의 원문)와 automatic(선별기가 고른 ID의 원문)을 따로 제공한다. oracle도 정답 값이나 구조화 결과는 프롬프트에 넣지 않는다. 자동 경로 평가의 기준도 동일한 사전 정답이다.
리뷰는 facts, wording, unknown, completeness를 독립 목록으로 기록한다. 원문과 다른 지원 가능한 숫자/단위, 존재하지 않거나 다른 근거의 ID는 사실 오류. 이름의 원문 불일치/출력 형식은 표현 오류. N/A, 모르는 표현, 상충·미확인 근거에서의 값 주장은 미확인이다. 줄 파싱 실패/잘림은 완전성 오류와 미확인을 남기며 사실 통과로 집계하지 않는다. failed는 facts 또는 completeness 오류, needs_review는 표현/미확인, passed는 모두 없는 경우이다. 기계의 passed는 이 제한된 출력 계약에서만 유효하다.

## 사전 평가 고정

cases.json은 구현·모델 실행 전에 작성한 합성 개발/보류 평가와 기대 결과다. 실제 12건은 이미 관찰한 개발/회귀 자료로만 사용한다. 사례 작성·판정은 에이전트가 수행했고 독립된 사람의 정답 검토는 아직 없다. 합성 보류 평가는 엔지니어링 점검이며 실제 일반화/논문 평가가 아니다.
원문/기대 결과/평가 정책은 lock.json의 SHA256으로 고정한다. runner는 해시 불일치 시 중단하고 각 실행에 입력과 lock을 복사한다. 보류 평가 결과를 보고 규칙을 수정하면 다음 버전에서 해당 사례는 개발 사례로 이동하고 새로운 보류 평가가 필요하다. 시스템 실행 버그 수정과 의미 규칙 변경은 구분해 기록한다.
사례에는 기간·시간 각각/동시/결측, 비교육, 충돌, 사용자/ID 오류, 과장된 응답, N/A, 지원 외 표현, 긴 입력을 포함한다. 고정 Qwen revision 989aa7980e4cf806f80c7fef2b1adb7bc71aa306, FP32, eager, greedy, seed42, 입력2048/출력256. 긴 입력은 실제 tokenizer로 검사하고 초과는 input_overflow로 저장, 자르지 않는다.

## 종료와 분기

종료: 계약+구조화+고정 사례+분리 평가+회귀/경계 테스트+실행 결과/제한을 남긴다. 소프트웨어 테스트 통과와 모델 품질을 별도로 보고한다. 자동 사용자 표시의 승격 기준은 평가된 사례의 사실/ID 오류 0, 이름/ID 보존 100%, 미확인 자동승인 0이며 미확인 수와 선별 재현율을 함께 보고한다. 소규모 합성 결과만으로 운영 승격하지 않는다.
필수 유형/시간이 없으면 BE 계약 보완으로 분기한다. 요청 필드: 교육/자격/수상/교과성적 구분의 정의·enum, 수료 여부, 기간 value/unit 또는 실제 수강 시작/종료, 실제 이수량 value/unit(계획량과 분리), 필드별 미제공/해당없음/미확인 상태, 원문 위치와 발급기관 출처, schema version. BE 팀에 전송하지 않고 요청안으로만 보관한다.
정답 근거를 줘도 생성 오류가 남으면 교육명/ID/기간 표시는 원문 기반으로 유지하고 모델 역할 축소 또는 별도 비교 Work로 분기한다. 논문 C는 실제 검증 증거와 독립 평가 프로토콜을 갖춘 별도 작업이다.
