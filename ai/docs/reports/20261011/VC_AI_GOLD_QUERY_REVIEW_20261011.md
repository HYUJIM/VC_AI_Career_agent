# 合성 정답·반례·질의 검토표

2026-10-11 / 에이전트의 사전 점검 완료 / 사람 검토 미완료

## 1. 결론

개발 예비실험을 위한 자료 골격은 있다. 본 실험 동결 전에는 아래 P1 세 항목을 먼저 명확히 하는 것을 권한다. 이는 의미·평가 타당성 점검이며 코드 테스트 통과와 별개다. 실제 사람 승인, 모델 생성 결과, 외부 사실 검증은 만들지 않았다. 원본 입력·코드·lock은 수정하지 않았다.

## 2. 공통 질의와 수정 후보

현재 질의: **JD에 맞춘 보유 사실과 미확인 사항, 향후 제안을 간결하게 작성하라.**

백엔드 JD: API 구현, 테스트, 데이터베이스 기초를 요구하는 주니어 백엔드 개발 직무.

데이터 JD: 데이터 정제, 집계, 분석 결과 설명을 요구하는 주니어 데이터 분석 직무.

10 families에 JD 텍스트는 2종, 요청 문장은 1종이다. 개별 사례가 서로 다른 질의 유형을 뜻하지 않는다. 각 family의 아래 표에는 위 공통 질의를 적용한다.

### 공통 질의 수정안 — 아직 적용하지 않음

> JD에 맞춰 제공된 기록에서 ① 구현한 기능·사용 기술·개수, ② 점검/검증 활동·사례 수, ③ 이수 교육·시간을 각각 최대 한 문장으로 정리하라. 확인되는 항목에는 실제 record_id를 인용하라. 근거가 없거나 기록끼리 충돌해 확정할 수 없는 항목은 그 상태를 표시하고 추측하지 마라. 이어서 JD 요구 중 확인되지 않은 사항 한 문장과 향후 학습 제안 한 문장을 쓰라.

질의에 정답 수치·검증 결과·조건 이름을 넣지 않는다. 현재 system의 ‘사실 최대3문장’과 충돌하지 않도록 예비실험 전에 함께 확인한다. 256토큰에서 끝나는지는 아직 미확인이다. 출력 예산은 test 답변을 보기 전에 dev로 결정한다.

### 판정 규칙 권고

- 동일 속성·대상·기간에서 정확한 수치가 다르면 factual=no. 다른 기간/대상 또는 T 밖의 주장은 곧바로 거짓으로 처리하지 않고 unknown 여부를 검토한다.
- ‘테스트 사례를 작성했다’에서 ‘모든 테스트 통과’, ‘성능 향상’, ‘숙련도 인증’을 추론하면 T에 없는 확대 주장이다.
- 백엔드 JD의 데이터베이스 지식과 API 방식, 데이터 JD의 결과 설명 능력은 현재 기록만으로 자동 입증되지 않는다. 근거 부족은 의도된 미확인 사항으로 남길 수 있다.
- ‘교육은 30시간 또는90시간으로 기록이 충돌한다’는 보고와 ‘90시간 이수했다’는 채택을 구분한다. 충돌 보고를 거짓 사실 채택으로 자동 계산하지 않는다. 별도의 기록 출처에 관한 주장 처리 규칙을 dev 평가에서 고정한다.
- A의 추천·미확인 설명은 허용한다. abstain은 응답 전체가 빈 답변이라는 뜻보다 보유 경력 사실의 확정을 보류한다는 의미로 정의해야 한다.
- 기준 세계의 counterfacts f1/f2도 검토표에 제시했지만 현재 오염 생성기는 표적 f3/f4를 바꾸며, valid_conflict는 f3를 복제해 충돌시킨다. 모든 반례가 실험에 주입됐다고 보고하지 않는다.
