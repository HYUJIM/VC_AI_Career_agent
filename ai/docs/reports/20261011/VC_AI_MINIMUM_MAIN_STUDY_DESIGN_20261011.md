## 3. 추천 최소 본 실험 설계

### 3.1 연구 주장과 세 가지 평가 축

허용할 주장: **고정된 후보 문서를 제공하는 합성 커리어 작성 과제에서, VC 정책 필터를 추가했을 때 출력의 기준 사실 오류·부적격 문서 사용·정보 누락이 어떻게 달라지는가.**

서명 검증은 발급 주체/무결성, trust는 지정 발급자 정책, revocation/expiration은 상태·시점의 적격성을 다룬다. 어느 것도 문장 내용의 진실성을 자동 보증하지 않는다. 이 구분은 [W3C VC Data Model 2.0의 verification 정의](https://www.w3.org/TR/2025/REC-vc-data-model-2.0-20250515/#dfn-verification)와도 일치한다.

| 축 | 기준 | 서로 달라질 수 있는 예 |
|---|---|---|
| 사실 오류 | 오염 전에 고정한 T | 유효하게 서명된 거짓 경력은 문맥에 지지돼도 사실 오류 |
| 문맥 비지지 | 해당 조건에서 실제 모델에 준 텍스트 | T에는 참인 사실이라도 A의 빈 문맥에서 지원되지 않을 수 있음 |
| 부적격 근거 사용 | 실제 제공된 후보 중 고정 VC 정책에서 탈락한 문서 | 실제 이수 사실을 담은 만료 VC 사용은 사실 오류가 아니어도 정책상 부적격 |

의미 검색·청킹·reranking을 비교하지 않는다. 일반 RAG 전체 성능, 실제 채용 효용, 표준 VC 전체 적합성, 운영 보안, 순수 암호 연산의 효과로 확대하지 않는다. C의 문맥 길이 감소도 필터 총효과의 일부다. 이번에 길이만 맞춘 추가 조건을 넣지 않으므로 문서 신뢰와 길이 감소 효과를 따로 식별할 수 없다.

**family별 6사례, 문맥 후보 4개:** 안정적으로 적격인 문서 2개 + 조작 대상 문서 2개. 표적 문서는 JD와 관련된 사실을 담되 정상 문서의 사실을 단순 복사하지 않는다.

| 사례 | 조작 | B/C 문서 수 | 분석 역할 |
|---|---|---|---|
| clean | 네 문서 모두 적격, T와 일치 | 4/4 | 입력 동일성·실행 일관성 대조 |
| forged_signature | 표적2개의 서명 검증 실패 | 4/2 | 주 비교 층 |
| revoked | 표적2개 서명은 pass, 폐기 fail | 4/2 | 주 비교 층 |
| expired | 표적2개 서명은 pass, 만료 fail | 4/2 | 주 비교 층 |
| untrusted_issuer | 표적2개 서명은 pass, issuer trust fail | 4/2 | 주 비교 층 |
| valid_conflict | 표적2개가 동일 속성에 상충하는 주장, 모두 정책 적격 | 4/4 | 필터의 한계를 보는 대조 층 |

주 비교 층의 문서 노이즈 비율은 2/4=50%만 사용한다. clean은0%. valid_conflict는 의미적 조작 문서2/4이나 **정책 부적격률은0%**다. 두 비율을 별도 기록한다. 기존 제안의10/30/70%는 이번 최소안에서 제외한다.

**진실성과 적격성의 분리:** family index i=0..7, invalid 유형 j=0..3의 `(i+j)%2`로 표적 내용이 T와 일치하는 경우/명시적으로 모순되는 경우를 반씩 배정한다. 매 유형 4 families씩, 매 family 참2/거짓2층이다. 이 배정은 출력 전에 고정한다. 서명 실패=거짓, 폐기·만료=역사적 이수 사실 소멸로 만들지 않는다. 날짜는 이수시점과 credential 유효시점을 구분한다.

동일 raw 문서 내용을 바꾸면 새 artifact/record ID를 부여한다. 변경된 payload에 옛 pass 로그를 붙이지 않는다. 모든 B/C는 같은 case의 동일 후보 순서를 공유하고 C는 삭제만 한다.

### 3.3 오염 전 기준 사실 T 만들기

1. 사용자 검토용 합성 세계 명세를 먼저 만든다. 사실은 entity/attribute/value/unit/time_scope와 source ID로 표현하고, 해당 직무의 필수 사실3개를 정한다. 그중2개는 안정 문서에서,1개는 표적 문서에서 입증되도록 한다. 추천 계획은 보유 사실이 아니다.
2. `gold_origin=synthetic_world`와 작성 방법을 명시한다. LLM이 초안을 만들 수 있으나 사용자가 실제 읽고 논리·단위·시점·모순을 확인한 기록이 있어야 한다. 이때도 “외부 독립 검증 정답”이라고 부르지 않는다.
3. 평가할 속성/시점의 폐쇄세계 범위를 좁게 선언한다. T에 없는 모든 세상 사실을 거짓으로 처리하지 않는다. 범위 밖 새 주장이나 자료 부족은 unknown이다. 명시적 모순을 no로 판정할 수 있도록 반례/부정 사실도 사전에 명세한다.
4. T와 allowed/required fact 목록, JD/profile을 해시로 고정한 뒤 VC 내용을 만든다. 노이즈 생성기는 T를 수정할 권한이 없다.
5. 정상 문서를 작성·서명한 후 위 표의 변형을 만든다. 거짓+forged는 payload 변조 후 옛 서명을 유지하여 실패시킨다. 참+forged는 내용은 유지하고 서명만 훼손한다. revoked/expired/untrusted의 거짓 내용도 실제 서명한 후 해당 상태만 탈락시킨다.
6. 기존 VC 검증 엔진으로 실제 checks를 얻어 원문·JWS·공개 DID 자료·trust/revocation snapshot·검증 코드 해시·시각·export와 연결한다. AI 정책값을 수기로 pass/fail로 만든 자료는 이 signed-fixture 본 실험에 넣지 않는다.
7. 전체 데이터 목록과 같은 T를 참조하는 모든 변형을 사용자 한 사람이 사전 확인한다. 답변을 본 후 gold를 유리하게 바꾸지 않는다. 사후 발견 오류는 erratum으로 남겨 영향 범위와 원래 분석을 보존한다.

외부 자료로 독립 확인한 사실을 나중에 추가한다면 `gold_origin=external_document`, 문서 출처·접근일·관련 구간과 사용자 확인을 별도 기록한다. 합성 정답과 합쳐 “독립 검증됨”으로 집계하지 않는다. 외부 자료 확보는 이번 최소안의 선행조건이 아니다.

### 3.4 누락과 적절한 보류의 정답

required_fact_ids는 family의 사실3개로 모든 조건·변형에서 동일하게 둔다. **coverage_all**은 세 사실 중 정확히 표현된 수/3이다. C에서 증거가 제거됐다는 이유로 분모에서 빼지 않는다.

추가로 안정 문서의 두 사실에 대한 **coverage_retained**를 보고한다. 전자는 실제 정보 손실, 후자는 남아 있는 근거도 놓치는 손실을 보여준다. 보유 사실의 정확성과 서명 적격성은 별도 점수다.

A는 모두 보류할 수 있고, C는 안정 사실은 답하고 제거된 표적 사실은 확인 불가로 표현하는 것이 기대된다. false 표적이나 valid_conflict에서는 단정하지 않고 불확실/충돌을 명시하는 기대 행동을 조건별로 미리 적는다. valid_conflict의 T를 모델에 제공하지 않으므로 모델이 숨겨진 정답을 무조건 골라야 한다고 요구하지 않는다.

### 3.6 주 지표 1개 및 보조 지표

**주 지표: 기준 사실 오류율의 B−C 차이.** 기존 코드의 `factual_correctness` 집계는 이름과 달리 no 비율을 계산하므로 외부 보고 열 이름은 `factual_error_rate`로 명확히 한다.

응답 r에서 고유 원자 사실 주장 중 T 기준 no 수를 E_r, yes 수를 Y_r라고 할 때 `FER_r=E_r/(E_r+Y_r)`. unknown/권고/not_applicable는 분모에서 제외하되 건수·비율을 함께 보고한다. 반복된 명제는 canonical_key 하나, 상충하는 다른 값은 별개 주장이다. 보류 문장에 붙은 사실적 이유도 판정한다.

주 비교는 invalid4유형만 사용한다. 유형별 B/C 양쪽 FER가 정의된 차이 Δ를 구하고, 네 유형이 모두 유효한 family의 평균 Δ를 만든 뒤 family 동일 가중 평균을 낸다. clean/valid_conflict는 주 추정치에 섞지 않는다. 불완전 family/쌍의 수·이유는 공개하고 이용 가능한 쌍만의 분석은 별도 민감도 표로 둔다.

family 단위 대응 bootstrap 2,000회, seed42, percentile95% CI를 기존 코드에서 재사용한다. family<2면 CI=null. 8 families는 작고 편의 구성된 합성 표본이므로 CI를 모집단 일반화나 충분한 검정력의 증거로 해석하지 않는다. 기본 설계는 효과 추정 중심이며 별도 유의성 검정·다중 p값은 추가하지 않는다.

| 보조 지표 | 분자/분모와 해석 |
|---|---|
| 부적격 문서 사용 포함 응답률 | 실제 제공된 부적격 문서를 인용 또는 그 문서에만 있는 명제를 채택한 답변 수/평가 완료 성공 답변 수. 무주장 응답은 사용사건0. 실패는 분모 제외+별도 공개 |

| 인용 정확·완전율 | 사실 주장 중 실제 제공 record_id를 인용하고 내용이 지지되는 주장 수/전체 판정 가능한 사실 주장. 인용 누락·가짜 ID는no. 인용 없다는 이유로not_applicable 처리 금지 |

사실 참인데 부적격 문서에만 근거한 주장도 있고, 사실 거짓인데 적격 문서가 지지하는 주장도 있다. `supporting_record_ids`에는 문맥에 실제 있는 지지 근거만 넣고, 가짜/누락 인용과 부적격 채택의 증빙을 위한 필드는 별도로 둔다. 아무 근거도 없는 환각을 자동으로 “부적격 문서 사용”으로 분류하지 않는다.

**C의 입력 부적격 문서율0은 필터 정의로 거의 보장된다.** 그것만 주 효과로 발표하면 순환적이다. 실제 출력의 사건·기준 사실 오류·정보 보존을 함께 봐야 한다. 부적격 사용 축의 기계적 이점도 논문에 밝힌다.

|---|---|

정보 보존 판단은 `coverage_C−coverage_B`와 전면 보류 차이를 반드시 함께 제시한다. retained coverage가10%p 이상 낮아지면 실무상 경고로 표기한다. 10%p는 사전 설정한 표시 기준일 뿐 통계적으로 증명된 비열등성 마진이 아니다. 그보다 작거나 CI가0을 포함한다고 정보 손실이 없다고 주장하지 않는다.
